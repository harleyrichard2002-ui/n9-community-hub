# N9 Community Hub
Starter application, not deployed. Uses Supabase Auth and database row-level security, with Vite on Netlify. No service key needed in browser. Run schema.sql once in Supabase SQL Editor (new hub tables). Enable email/password and optionally Discord OAuth in Supabase Auth; set Site URL and redirect URLs to deployed site. Create an administrator email/password account in Authentication > Users (confirm email), copy its UUID and run: INSERT INTO public.hub_admins(id) VALUES ('ADMIN_UUID'); Then log in with that account. Members can use Discord OAuth or accounts you create in Supabase; unapproved accounts see their UUID. Admin adds that UUID and name in Admin panel. This is manual approval, not automatic Discord guild sync. Admin accounts should use strong unique passwords. Configure VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY in Netlify build environment, import this folder from GitHub and build (npm run build, dist). For local development create .env.local with those two variables, npm install, npm run dev. Do not expose secret/service-role keys. Chat and support refresh every five seconds when not typing; media uses HTTPS links, not file uploads. Giveaways accept one entry per member and can be closed; automatic winner selection/deadlines not implemented. Warnings are counts, not reason history; rankings are manual; no audit trail or suspension controls yet. Activity is self-reported daily UTC check-ins. Test access controls with separate admin/member accounts before production. No automatic Discord member sidebar, presence, or avatar sync in this starter. SQL and browser integration have not been tested against a live Supabase project.
